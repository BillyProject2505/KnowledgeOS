# 7.1 Visual Foundation

## Purpose

### Purpose

Define the canonical Visual Design System (VDS) governing every visual Communication Artefact produced under the Coz We Care Production Bible (CPB).

The Visual Design System establishes the universal visual production knowledge required to translate communication decisions into consistent visual implementation before production begins.

---
### Canonical Decision

The Visual Design System (VDS) is the single canonical source governing visual production knowledge within the Production Bible.

The VDS defines visual production knowledge only.

Communication decisions SHALL originate from upstream chapters.

Visual implementation belongs exclusively to the Visual Design System.

---

## Rules

### VDS-001

The Visual Design System SHALL translate communication decisions into visual implementation.

### VDS-002

The Visual Design System SHALL NOT redefine communication decisions established by:


- Foundation
- Brand System
- Audience System
- Content Strategy
- Content Architecture
- Editorial System

### VDS-003

Visual implementation SHALL preserve canonical visual identity.

### VDS-004

Visual implementation SHALL prioritize consistency over stylistic variation.

### VDS-005

Visual implementation SHALL remain deterministic, reusable, and machine-readable.

### VDS-006

Visual implementation SHALL inherit upstream production knowledge.

---

## Visual Translation Principle

> **Visuals Never Decide. Visuals Translate.**

The Visual Design System exists solely to translate previously established communication decisions into visual implementation.

The VDS SHALL NOT create communication decisions independently.

---

## Communication Flow

```text
Foundation
        ↓
Brand System
        ↓
Audience System
        ↓
Content Strategy
        ↓
Content Architecture
        ↓
Editorial System
        ↓
Visual Design System
        ↓
Audience Experience
```

The Visual Design System is the final production layer before audience consumption.

Every visual implementation SHALL remain traceable to upstream production decisions.

---

## Visual Design Principles

### VDP-001

Translation Before Decoration

Visual implementation SHALL prioritize communication over decoration.

---

### VDP-002

Identity Before Creativity

Canonical identity SHALL take precedence over stylistic variation.

---

### VDP-003

Identity Is Inherited

Canonical identity assets SHALL be inherited.

They SHALL NOT be recreated.

---

### VDP-004

Consistency Builds Trust

Consistent visual implementation SHALL strengthen recognition, trust, and production quality.

---

### VDP-005

System Before Artwork

Every visual artefact SHALL be treated as an implementation of the Visual Design System.

---

### VDP-006

Reverse Engineer Before You Standardize

Visual standards SHALL be derived from validated Coz We Care production artefacts before becoming canonical standards.

---

# 7.2.2 Typography System

## Purpose

### Purpose

Define the canonical typography vocabulary of the Coz We Care Visual Design System (VDS).

The Typography System establishes the canonical typography language governing every Communication Artefact produced under the Coz We Care Production Bible (CPB).

The Typography System defines:

- Canonical Typefaces
- Canonical Typography Tokens
- Typography Governance
- Typography Relationships
- Typography Inheritance

The Typography System SHALL NOT define typography implementation, layout, spacing, positioning, or visual composition.

---

### Canonical Decision

The Typography System is the single canonical source governing typography within the Visual Design System.

Every Communication Artefact SHALL inherit its typography vocabulary from this section.

Typography SHALL be selected according to **Communication Role**, not visual preference.

AI SHALL use Canonical Typography Tokens as the only valid typography vocabulary.

Typography terminology SHALL follow the **Terminology Uniqueness Principle (TUP)**.

---

## Typography Governance

### Primary Typeface

| Typeface | Status |
|----------|--------|
| Montserrat | Canonical |

Montserrat SHALL be the official typeface of Coz We Care.

---

### Fallback Typefaces

| Typeface | Priority |
|----------|----------|
| Poppins | Secondary |
| Inter | Tertiary |
| Nunito Sans | Quaternary |

Fallback Typefaces SHALL only be used when the Primary Typeface cannot be rendered due to platform limitations, operating system constraints, software compatibility, or production environment restrictions.

Fallback Typefaces SHALL NOT be selected based on stylistic preference.

---

### Governance Principle

**One Communication Role, One Typography Token**

Each Communication Role SHALL map to exactly one Canonical Typography Token.

Typography Tokens SHALL NOT be used interchangeably unless explicitly defined by the Production Bible.

---

## Canonical Typography Tokens

### Hero Title

Primary entry point of a Communication Artefact.

Represents the highest level of visual attention.

---

### Content Title

Primary title introducing the content of a slide or visual section.

---

### Supporting Title

Typography supporting or extending the Content Title.

---

### Body Text

Primary explanatory and educational typography.

Optimized for readability.

---

### Label Text

Typography attached to illustrations, diagrams, icons, and visual components.

---

### Badge Text

Typography used inside badges, labels, category indicators, and permanent visual markers.

---

### Interactive Text

Typography encouraging acknowledgement, participation, interaction, or audience response.

Interactive Text SHALL NOT be interpreted as Editorial Call-to-Action (CTA).

---

### Footer Text

Typography used exclusively by the Canonical Footer System.

Footer Text SHALL only be implemented through Footer Specification.

---

Hero Title SHALL remain the highest level of visual attention.

Body Text SHALL support the overall communication.

---

### Supporting Hierarchy

Label Text

Badge Text

Footer Text

Supporting Typography SHALL reinforce communication without competing with the Primary Hierarchy.

Supporting Typography SHALL NOT become the primary visual focus.

---

### Interactive Hierarchy

Interactive Text

Interactive Text SHALL encourage audience participation without replacing the primary communication objective.

# 7.2.3 Canonical Character System

## Purpose

### Purpose

Define the permanent presenter identity of the Coz We Care Visual Design System (VDS).

The Canonical Character System establishes the permanent visual identity representing Coz We Care across all Communication Artefacts.

The Canonical Character is a permanent Identity Asset.

It SHALL NOT be treated as a Decorative Illustration Asset.

The Canonical Character SHALL remain visually recognizable, semantically consistent, and stylistically identical throughout the entire Production Bible ecosystem.

---

### Canonical Decision

The Canonical Character is the single canonical presenter identity of Coz We Care.

Every Communication Artefact containing a presenter SHALL inherit the Canonical Character defined by this section.

The Canonical Character SHALL preserve:

- Canonical Identity
- Rendering Identity
- Visual Recognition

Only Adaptive Appearance MAY change.

---

## Character Governance

### Canonical Character

**Status**

Identity Asset

**Role**

Permanent visual representative of Coz We Care.

The Canonical Character SHALL remain consistent throughout every Communication Artefact.

---

### Decorative Characters

**Status**

Illustration Asset

**Role**

Support visual communication.

Decorative Characters SHALL support communication.

Decorative Characters SHALL NOT replace, imitate, compete with, or be mistaken for the Canonical Character.

---

## Character Identity Model

The Canonical Character consists of three independent identity layers.

---

### Layer 1 — Canonical Identity

The following attributes SHALL remain permanent.

- Face
- Facial Structure
- Hair Style
- Hair Color
- Skin Tone
- Approximate Age
- Body Proportion
- Facial Features

Canonical Identity SHALL remain unchanged across every Communication Artefact.

---

### Layer 2 — Rendering Identity

Rendering Identity defines how the Canonical Character is visually represented.

The following attributes SHALL remain permanent.

- Rendering Style
- Rendering Technique
- Facial Realism
- Lighting Style
- Material Appearance
- Detail Fidelity
- Visual Fidelity

Rendering Identity SHALL remain visually identical across every production.

---

### Canonical Rendering Style

**Rendering Style**

Photorealistic Digital Human

**Definition**

A high-quality digital human representation with realistic human proportions, realistic facial features, realistic skin texture, realistic lighting, and realistic material rendering.

The Canonical Character SHALL appear visually comparable to a professionally rendered digital human.

The Canonical Character SHALL maintain the same rendering style demonstrated by the canonical Coz We Care visual assets.

The Canonical Character SHALL NOT change rendering style between Communication Artefacts.

---

### Forbidden Rendering Styles

The Canonical Character SHALL NOT be rendered as:

- Flat Design
- Flat Illustration
- Vector Illustration
- Cartoon
- Anime
- Manga
- Chibi
- Pixar-style Character
- Ghibli-style Character
- Semi-realistic Illustration
- Watercolor
- Oil Painting
- Pencil Sketch
- Ink Drawing
- Low-poly 3D
- Stylized Illustration
- Pixel Art
- Clay Render
- Comic Style

---

### Layer 3 — Adaptive Appearance

The following attributes MAY change according to communication requirements.

- Clothing
- Pose
- Facial Expression
- Gesture
- Accessories
- Props

Adaptive Appearance SHALL support communication without altering Canonical Identity or Rendering Identity.

---

## Character Relationships

### Identity Hierarchy

Canonical Identity

↓

Rendering Identity

↓

Adaptive Appearance

Identity SHALL take precedence over Rendering.

Rendering SHALL take precedence over Appearance.

---

### Character Hierarchy

Canonical Character

↓

Decorative Characters

Decorative Characters SHALL remain subordinate to the Canonical Character.

---

## Character Inheritance

The Canonical Character SHALL be inherited by:

- Hero Pattern
- Educational Carousel
- Information Slides
- Awareness Campaigns
- Promotional Content
- Storytelling Content
- Social Media Communication Artefacts

Every inherited implementation SHALL preserve both Canonical Identity and Rendering Identity.

---

## Canonical Character Principles

### CCP-001

**Identity Persists. Appearance Adapts.**

Canonical Identity SHALL remain permanent.

Adaptive Appearance MAY change.

---

### CCP-002

**Identity Before Illustration.**

Identity SHALL always take precedence over illustration.

---

### CCP-003

**Identity Includes Rendering.**

Rendering Identity SHALL be treated as an inseparable part of the Canonical Character.

Rendering SHALL remain permanent.

---

### CCP-004

**Consistency Builds Recognition.**

Consistent Character Identity strengthens audience recognition, trust, and long-term brand continuity.

---

## Rules

### CCS-001

Canonical Identity SHALL remain unchanged.

---

### CCS-002

Rendering Identity SHALL remain unchanged.

---

### CCS-003

Adaptive Appearance MAY change according to communication requirements.

---

### CCS-004

---

### CCS-005

---

### CCS-006

### CCS-008

AI SHALL preserve both Identity Consistency and Rendering Consistency across every production.

---

### CCS-009

# 7.4 Visual Specification

# 7.4.1 Canvas System

## Core Object

**Canvas**

---

## Purpose

Define the Canvas System of the Coz We Care Visual Design System (VDS).

The Canvas System governs the rendering foundation upon which every Communication Artefact is produced.

Canvas establishes the rendering medium before any visual element is positioned or rendered.

Canvas System SHALL NOT govern:

- Visual Language;
- Communication Structure;
- Layout Behavior;
- Editorial Strategy.

---

## Canonical Decision

Canvas System is the single canonical source governing Canvas throughout the Coz We Care ecosystem.

Canvas System SHALL define:

- Canvas;
- Canvas Foundation;
- Canvas Specifications;
- Canvas Consistency.

Canvas System SHALL NOT define:

- Communication Artefacts;
- Communication Structure;
- Layout Specifications;
- Visual Language;
- Editorial Strategy.

---

## Canonical Object

The Canvas System contains one Canonical Object.

**Canvas**

Canvas SHALL become the rendering foundation inherited by every Communication Artefact.

Every Communication Artefact SHALL be rendered upon the Canvas.

---

## Canonical Responsibility

Canvas determines the rendering medium before any rendering decision is made.

No other domain within the Production Bible SHALL determine the rendering medium.

---

## Domain Boundary

Canvas System governs the rendering medium only.

Canvas System SHALL NOT determine:

- communication flow;
- communication zones;
- layout behavior;
- element placement;
- visual language;
- editorial objectives.

These responsibilities remain exclusively governed by their respective canonical domains.

---
