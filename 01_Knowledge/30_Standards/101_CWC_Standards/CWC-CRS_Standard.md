# CWC-CRS Standard
## Reference Sheet Layout Standard

**Document ID:** CWC-CRS-STD-001  
**Status:** Canonical Draft  
**Scope:** All Canonical Reference Sheets (CRS) within the Coz We Care Canonical Asset System.

---

# 1. Purpose

The **Reference Sheet Layout Standard** defines the presentation framework shared by every Canonical Reference Sheet (CRS).

Its purpose is to ensure that every Canonical Asset is documented using a consistent visual structure, making Reference Sheets easy to read, compare, maintain, and interpret by both humans and AI systems.

This standard governs **presentation only**. It does **not** define, modify, or extend the canonical specifications of any asset.

All Canonical Decisions and asset specifications remain the responsibility of the corresponding **CWC Canonical Asset Bible (CWC-CAB)**.

---

# 2. Design Principles

Every Reference Sheet should answer one fundamental question:

> **"What is the authoritative visual representation of this Canonical Asset?"**

The CWC-CRS complements the CWC-CAB by presenting the asset visually rather than descriptively.

The layout shall prioritize:

- Visual Clarity
- Technical Precision
- Consistency
- High Information Density
- Modular Organization
- AI Readability

Every page shall contain a standardized header.

### Left

- Coz We Care Logo

### Center

- Asset Name

### Right

- Object Identifier
- Asset Identifier
- Version
- Page Number

---

# 6. Content Area

The content area is divided into two functional zones.

## 6.1 Primary Display Area

Reserved exclusively for the Canonical Asset and its visual representation.

Typical content includes:

- Official Artwork
- Construction Drawings
- Geometry
- Alignment Guides
- Spacing Diagrams

## 6.2 Annotation Area

Reserved for:

- Labels
- Measurements
- Callouts
- Technical Notes
- Cross References

Annotations shall never obscure the Canonical Asset.

---

### Left

- Coz We Care Canonical Asset System
- Canonical Reference Sheet

- Document Identifier

### Right

- Revision
- Lifecycle Status

# 9. Layout Colors

The document layout shall remain visually neutral.

Recommended colors:

- White
- Black
- Neutral Gray

Brand colors shall be used only when representing the Canonical Asset itself.

---

# 10. Reference Frame

Every visual object shall be displayed within a Reference Frame to ensure:

- Consistent Positioning
- Measurement Consistency
- Construction Overlays
- Comparative Scale

Border Specification:

- 1 pt Light Gray

---

# 11. Callout Style

Callouts shall use:

- Thin Gray Leader Lines
- Circular Endpoints
- Numbered Markers
- Concise Labels

---

# 12. Measurement Style

Supported measurement units:

- Millimetres (mm)
- Pixels (px)
- Percentages (%)

Dimension labels shall remain horizontal whenever practical.

---

# 13. Standard Section Order

Unless an asset requires otherwise, Reference Sheets should follow this sequence:

1. Cover Reference
2. Asset Overview
3. Construction
4. Geometry
5. Dimensions
6. Typography
7. Color Reference
8. Component Anatomy
9. Spacing
10. Clear Space
11. Approved Variants
12. Usage Reference
13. Metadata

---

# 14. Asset Placement Rule

The Canonical Asset shall remain the primary visual focus.

Recommended allocation:

- Canonical Asset: **70–80%**
- Annotations and Metadata: **20–30%**

---

# 15. White Space

Generous white space shall be preserved to:

- Improve Readability
- Separate Technical Information
- Prevent Annotation Overlap
- Emphasize the Canonical Asset

# 17. Compliance Principles

Every Reference Sheet shall comply with the following principles:

- **Consistency** — A unified visual language across all CWC-CRS documents.
- **Neutrality** — The layout supports the asset without competing with it.
- **Modularity** — Sections can be reused across different asset categories.
- **Scalability** — Suitable for both simple and complex assets.
- **Traceability** — Every visual element shall be directly traceable to the corresponding CWC-CAB specification.
- **Non-Authoritative** — A CWC-CRS shall never introduce, modify, interpret, or extend any Canonical Decision.

---

# Editorial Notes

This standard defines the **presentation architecture** for all Canonical Reference Sheets.

It intentionally separates **presentation** from **specification**:

- **CWC-CAB** defines the Canonical Specifications.
- **CWC-CAR** identifies and registers the Canonical Asset.
- **CWC-CRS** provides the authoritative visual representation of the Canonical Asset.
- **CWC-CAS** defines the architecture governing the Canonical Asset System.

This separation preserves a clear Single Source of Truth while ensuring every Canonical Asset can be represented consistently across the entire Coz We Care Canonical Asset System.
