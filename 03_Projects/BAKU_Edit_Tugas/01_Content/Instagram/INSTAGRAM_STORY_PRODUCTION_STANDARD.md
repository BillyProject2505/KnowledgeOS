# BAKU Edit Tugas — Instagram Story Production Standard

**Version:** 1.1  
**Date:** 2026-09-05  
**Status:** APPROVED

## Purpose

Dokumen ini adalah standar reusable untuk produksi Instagram Story BAKU Edit Tugas. Dokumen ini mengatur system produksi visual dan QC, bukan strategi konten atau copy untuk workstream tertentu.

Content-specific requirements tetap disimpan pada folder/content document masing-masing.

## Scope

Berlaku untuk:

- Instagram Story statik;
- Story Highlight;
- Story series yang menggunakan identitas visual BAKU Edit Tugas.

Tidak mengatur:

- Feed/poster;
- Reels/video;
- caption strategy;
- hashtag strategy;
- platform ranking claims;
- content strategy spesifik suatu campaign.

## 1. Canvas & Format

- Format: static Instagram Story.
- Aspect ratio: 9:16.
- Target size: 1080 × 1920 px.
- Output: static image.
- Video dan animation tidak digunakan kecuali ditetapkan secara eksplisit oleh brief baru.

## 2. Brand Asset Rules

Gunakan hanya canonical brand assets yang tersimpan di:

`02_Assets/Brand/`

Canonical logo:

- `BAKU_Edit_Tugas_logo-primary.png`
- `BAKU_Edit_Tugas_logo-transparent.png`

Rules:

- Jangan menggambar ulang logo.
- Jangan mengganti logo dengan hasil AI generation.
- Jangan stretch, distort, atau mengubah geometry/logo identity.
- Untuk series yang sudah memiliki baseline approved, posisi dan relative scale logo mengikuti baseline tersebut.
- Canva adalah finalization layer untuk logo placement, sizing, alignment, dan spacing.

## 3. Canonical Visual Baseline

Untuk FAQ Highlight saat ini, Story 1 yang telah disetujui menjadi visual baseline dan diperkuat oleh completed/published FAQ Story set sebagai reference set.

### 3.1 Fixed Visual Characteristics

Karakteristik berikut diperlakukan sebagai system-level baseline untuk FAQ dan sebagai reference utama saat membuat Story Highlight lain yang dimaksudkan untuk konsisten dengan sistem BAKU:

- warm cream/off-white background;
- deep navy primary;
- warm gold/yellow accent;
- dark navy/charcoal text;
- canonical BAKU logo dengan treatment konsisten;
- large bold question/hook sebagai first reading point;
- prominent rounded dark-navy answer box dengan gold answer text;
- flat editorial illustration dengan academic/student context;
- clean vector-like forms;
- friendly and approachable tone;
- restrained supporting objects;
- generous whitespace;
- consistent composition language;
- dedicated FAQ footer treatment di bagian bawah untuk FAQ Highlight.

### 3.2 Composition Grammar

Default composition grammar untuk Story yang mengikuti baseline ini adalah:

`Logo → Question/Hook → Answer Zone → Supporting Visual/Context → Main Illustration → Footer/CTA`

Functional zones:

1. **Logo zone** — fixed and protected.
2. **Question / hook zone** — dominant entry point.
3. **Answer zone** — strongest message hierarchy after the question.
4. **Supporting visual/context zone** — speech bubble, note, object, or contextual element when useful.
5. **Main visual field** — large illustration or relevant visual metaphor.
6. **Footer / CTA zone** — persistent footer only where the series uses one; CTA only when relevant to the content brief.

The overall structure should remain stable while illustration, character, scene, objects, speech bubble, visual metaphor, and copy vary.

### 3.3 Fixed vs Variable Elements

**Fixed / system-level:**

- canvas and aspect ratio;
- core palette relationship;
- logo treatment;
- question → answer hierarchy;
- rounded answer-box concept for FAQ baseline;
- overall composition grammar;
- visual tone;
- footer treatment for FAQ Highlight.

**Variable / content-level:**

- question;
- answer;
- supporting copy;
- character;
- scene;
- speech bubble content;
- objects;
- visual metaphor;
- supporting imagery.

Do not redesign the core system merely to make individual Stories appear different.

Untuk workstream lain, baseline dapat diadopsi setelah explicit approval. Adopsi tidak berarti seluruh variable elements harus identik.

## 4. Reusable Layout System

Gunakan struktur visual yang konsisten untuk series yang saling berhubungan.

Default functional zones:

1. Logo zone — fixed.
2. Question / hook zone.
3. Answer zone — strongest typographic hierarchy.
4. Supporting copy zone / visual context.
5. Visual field — flat illustration / relevant visual metaphor.
6. Trust / CTA zone — CTA hanya bila relevan dengan content brief.

Satu consistent alignment axis digunakan untuk text utama kecuali baseline yang telah disetujui secara eksplisit menentukan pola lain.

Variabel antar-Story:

- question;
- answer;
- supporting copy;
- character;
- scene;
- objects;
- visual metaphor;
- supporting imagery.

Jangan mengubah struktur inti hanya untuk membuat setiap Story terlihat berbeda.

## 5. Typography Standard

Typography hierarchy wajib konsisten dalam satu series:

- Question/hook: large, prominent, first reading point.
- Answer: strongest message after question.
- Supporting copy: secondary, compact, readable.
- CTA: visually distinct only when CTA exists.

Exact font family, font size, line height, and tracking mengikuti approved Canva baseline untuk series terkait.

Jangan mengarang numeric typography specification dari screenshot/raster image. Jika angka diperlukan, ambil dari Canva source.

## 6. Color Standard

Palette harus mengikuti approved brand/reference baseline.

Core relationship untuk FAQ baseline:

- Background: warm cream/off-white.
- Primary: deep navy.
- Accent: warm gold/yellow.
- Secondary text: dark navy/charcoal.

Warna baru boleh ditambahkan hanya jika diperlukan secara produksi dan tidak merusak brand hierarchy.

Jangan mengganti palette hanya demi novelty.

## 7. Illustration / Visual Asset Standard

Untuk FAQ baseline, gunakan flat editorial illustration.

Preferred characteristics:

- student/academic context;
- believable educational or consultation scenario;
- clean vector forms;
- consistent outline/treatment;
- navy/gold/cream relationship;
- restrained object density;
- visual hierarchy mendukung copy;
- sufficient negative space untuk typography.

Aset visual standalone preferred untuk placement manual ketika template Canva sudah dikunci.

Do not:

- place logo inside generated visual asset;
- generate replacement brand marks;
- add unnecessary slogans or claims into illustrations;
- add decorative UI/badges unless required by the content.

## 8. Safe Area Standard

Gunakan conservative working safe area:

- approximately 14% top;
- approximately 20% bottom;
- approximately 6% left/right.

Untuk 1080 × 1920 px, prinsip ini kira-kira berarti:

- top: ~269 px;
- bottom: ~384 px;
- sides: ~65 px.

Angka tersebut adalah working layout guidance, bukan klaim bahwa 1080 × 1420 px merupakan official Instagram safe-zone specification.

Exact pixel boundaries dapat dikunci lebih lanjut pada Canva source bila diperlukan oleh production baseline.

## 9. Copy Rules

- Gunakan copy sesingkat mungkin tanpa menghilangkan konteks yang dibutuhkan.
- Prioritaskan satu question, satu answer, supporting copy bila perlu, dan satu CTA bila relevan.
- Jangan menggunakan fixed word-count rule sebagai hard requirement.
- Jangan menambahkan copy baru hanya untuk mengisi ruang kosong.
- Jangan mengubah approved copy tanpa explicit revision.

## 10. CTA Rules

CTA hanya digunakan jika tujuan content memerlukan action.

Untuk series FAQ yang telah selesai:

- Story 4 memiliki CTA utama.
- Story lain tidak perlu CTA tambahan kecuali content brief menetapkannya.

CTA treatment harus:

- jelas sebagai action;
- tetap di dalam safe area;
- tidak mengalahkan question/answer hierarchy;
- tidak menggunakan unsupported performance claim seperti “2× better”.

## 11. Canva Production Rules

Canva adalah finalization layer.

Gunakan Canva untuk:

- typography;
- logo placement;
- alignment;
- spacing;
- copy;
- CTA;
- final visual QC;
- export.

Jika template/baseline sudah approved:

- jangan mengganti layout dasar tanpa explicit decision;
- jangan mengubah logo secara otomatis;
- jangan menggunakan AI-generated logo sebagai replacement;
- gunakan copy/content dari canonical content document.

## 12. Production Workflow

`Brief → Analysis → Content/Visual Plan → Asset Generation → Visual QC → Canva Finalization → Final QC → Export → State Sync`

Untuk series reusable:

`Approved Baseline → Story Prototype → QC → Replicate → Full-Series QC`

## 13. Visual QC Checklist

### Brand

- [ ] Canonical logo digunakan.
- [ ] Logo geometry/proportion tidak berubah.
- [ ] Palette sesuai approved baseline.
- [ ] Visual terasa sebagai BAKU Edit Tugas.

### Layout

- [ ] 9:16 / 1080 × 1920.
- [ ] Alignment konsisten.
- [ ] Question/hook berada pada first reading point.
- [ ] Answer memiliki dominant hierarchy.
- [ ] Supporting copy tidak overpowering.
- [ ] CTA hanya bila relevan.
- [ ] Core composition grammar tetap terbaca.

### Visual

- [ ] Illustration/asset mengikuti approved visual language.
- [ ] Visual mendukung message.
- [ ] Tidak terlalu ramai.
- [ ] Negative space cukup.
- [ ] No accidental branding or generated logo.

### Safe Area

- [ ] Important content berada dalam conservative safe area.
- [ ] Logo aman dari top UI region.
- [ ] CTA aman dari bottom UI region.

### Content

- [ ] Copy sesuai canonical content state.
- [ ] Tidak ada fabricated claim.
- [ ] Tidak ada fabricated statistics/social proof.
- [ ] Tidak ada unsupported absolute security/performance claim.

## 14. Approval Rules

### APPROVED

Gunakan hanya jika:

- visual system telah diperiksa;
- critical issues = 0;
- content sesuai canonical state;
- asset usage sesuai rules;
- Canva finalization selesai;
- final QC lulus.

### WORKING

Gunakan ketika desain sedang dikembangkan atau masih ada refinement yang diperlukan.

### DRAFT

Gunakan untuk eksplorasi yang belum disetujui.

### OPEN

Gunakan ketika keputusan produksi masih membutuhkan keputusan eksplisit.

### SUPERSEDED

Gunakan ketika baseline/decision sebelumnya digantikan oleh keputusan baru.

### BLOCKED

Gunakan ketika produksi tidak dapat dilanjutkan tanpa informasi atau asset yang wajib.

## 15. Non-Negotiable Rules

- No fabricated data.
- No fabricated sources.
- No fabricated testimonials/social proof.
- No unsupported performance claims.
- No unsupported absolute security/privacy claims.
- No AI-generated replacement logo.
- Do not change approved copy without explicit revision.
- Do not change an approved visual baseline without explicit decision.
- Do not add complexity without a functional reason.

## 16. Current FAQ Baseline Reference

The current FAQ production baseline is the user-approved Story 1 artifact together with the completed/published FAQ Story set as a supporting reference set.

Story 1 establishes the primary visual authority for:

- layout;
- relative typography sizing;
- spacing rhythm;
- logo placement/treatment;
- flat illustration language;
- color relationships;
- answer-box treatment;
- overall composition language.

The completed/published Story set demonstrates the approved system across multiple content variants. Future FAQ or adjacent Highlight Stories should change the content and visual metaphor while preserving the system-level characteristics above.

When exact numeric measurements are needed, the Canva source remains authoritative.

## 17. Reference Authority & Reuse

Use the following authority order for production decisions:

1. Explicit current project decision in `00_Context/DECISIONS.md`.
2. Approved Canva master/source for exact visual implementation.
3. This reusable production standard for system-level rules.
4. Approved exported PNG/reference artifacts for visual comparison and QC.

A raster reference must not be used to invent unsupported numeric specifications.

For reuse in a new Story Highlight workstream, inherit the system-level baseline first, then define and approve only the content-specific or series-specific deviations that are functionally required.

## 18. Change Control

Changes to this standard require explicit project decision and should be recorded in:

`00_Context/DECISIONS.md`

Changes to a specific Story series should be recorded in the relevant content directory rather than rewriting this standard.
