# SOP — Requirement Analysis

## 1. Tujuan

Mengubah request klien menjadi requirement produksi yang konkret, terukur, dan dapat digunakan sebagai dasar pengerjaan dan QC.

## 2. Prinsip

- Requirement adalah sumber kebenaran pekerjaan.
- Jangan mengubah tujuan akademik klien tanpa alasan dan tanpa konfirmasi bila perubahan substantif diperlukan.
- Bedakan `requirement`, `constraint`, `assumption`, dan `recommendation`.
- Setiap requirement yang dapat memengaruhi hasil akhir harus dapat diverifikasi pada tahap QC.

## 3. Klasifikasi Requirement

### A. Content

- tujuan tugas;
- pertanyaan/soal;
- topik;
- argumen atau poin wajib;
- batasan isi.

### B. Academic

- level pendidikan;
- jenis dokumen;
- metodologi bila relevan;
- sumber wajib;
- citation style;
- standar institusi/dosen/guru.

### C. Language & Style

- bahasa;
- tingkat formalitas;
- academic tone;
- terminology;
- preferensi gaya penulisan.

### D. Format

- file type;
- layout;
- font;
- spacing;
- margin;
- heading structure;
- page numbering;
- reference formatting.

### E. Delivery

- deadline;
- versi output;
- jumlah file;
- channel delivery;
- revision scope.

## 4. Prosedur

### Step 1 — Read All Available Instructions

Baca brief klien, soal, rubric, template, atau pedoman yang tersedia sebelum membuat keputusan editorial.

### Step 2 — Extract Requirements

Tuliskan requirement dalam bentuk poin yang dapat diperiksa.

Contoh:

`Requirement: dokumen menggunakan APA 7.`

Bukan:

`Requirement: sitasi harus bagus.`

### Step 3 — Identify Constraints

Catat batasan seperti jumlah halaman, jumlah kata, sumber minimal, deadline, format file, atau bagian yang tidak boleh diubah.

### Step 4 — Identify Ambiguities

Tandai requirement yang:

- bertentangan;
- tidak lengkap;
- tidak dapat diverifikasi;
- membutuhkan keputusan klien.

### Step 5 — Define Editing Scope

Tentukan dengan eksplisit apakah pekerjaan mencakup:

- copyediting;
- substantive editing;
- structural editing;
- citation/reference review;
- formatting;
- atau kombinasi.

### Step 6 — Create Production Brief

Ringkas hasil analisis dalam satu production brief yang akan menjadi acuan tahap diagnosis, editing, dan QC.

## 5. Output

Requirement Analysis menghasilkan:

1. Requirement list.
2. Constraint list.
3. Ambiguity/risk list.
4. Defined editing scope.
5. Production Brief.
6. Status: `READY`, `NEEDS_CLARIFICATION`, atau `BLOCKED`.

## 6. QC Requirement Analysis

- [ ] Semua instruksi utama sudah dibaca.
- [ ] Requirement ditulis secara konkret.
- [ ] Constraint dicatat.
- [ ] Ambiguitas ditandai.
- [ ] Scope editing jelas.
- [ ] Requirement penting dapat diuji pada final QC.
- [ ] Production Brief konsisten dengan request klien.
